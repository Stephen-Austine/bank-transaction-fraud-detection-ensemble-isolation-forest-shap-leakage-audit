# Data

All data in this folder is **synthetic** and safe to publish (10 distinct first names, 10 distinct last names, sequential customer IDs, a single transaction date, no emails/phones/addresses). See the main README for the evidence.

| Path | Rows | What it is |
|---|--:|---|
| `raw/complete_dirty_bank_transactions.csv` | 5,001 | The raw, deliberately dirty table (24 columns). Input to scripts `00`, `02`, `03`, `04` |
| `processed/cleaned_transactions.csv` | 4,638 | A pre-cleaned copy: 363 rows with missing values removed (2 of them fraudulent). Input to scripts `01` and `04` |
| `star_schema/dim_customer.csv` | 4,275 | Customer dimension *(not unique on `Customer_ID`, see the main README)* |
| `star_schema/dim_account.csv` | 1,133 | Account dimension |
| `star_schema/fact_transaction.csv` | 5,001 | Transaction fact table |

The three `star_schema/` files are generated by `src/00_export_star_schema.py` and can be re-created at any time.

## Target

`Is_Fraudulent`: 55 of 5,001 rows (1.10 %).

> **Heads-up:** `Risk_Score` perfectly separates this target (`Risk_Score > 0.75` ⇔ fraud), so it must **not** be used as a model feature. See the leakage audit in the main README.

## Replacing the data

To try the pipeline on your own transaction table, keep the same column names (or adapt the `features` lists in `src/02_*.py` / `src/03_*.py`) and put the file at `data/raw/complete_dirty_bank_transactions.csv`. If your data is real, **do not commit it**: add its path to `.gitignore` first.
